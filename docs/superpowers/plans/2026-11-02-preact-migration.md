# План миграции интерфейса на Preact

**Цель:** перевести интерактивный интерфейс Типографа на Preact без изменения его пользовательского поведения и способа публикации статического сайта.

**Текущее состояние:** React в проекте нет. `src/html/index.html` содержит готовую разметку, `src/index.ts` создаёт классы, работающие с DOM напрямую, Rollup собирает JS/CSS, а `tools/index.mjs` встраивает их и Typograf в корневой `index.html`. `npm test` запускает только ESLint и TypeScript; в текущем окружении `npm` недоступен, поэтому исходную сборку здесь не проверяли.

## Выбор границы миграции

1. **Рекомендуется: Preact для интерактивного редактора, статический HTML для описания страницы.** Перенести шапку, редактор, результат и настройки в один корневой компонент; переключатель языка в подвале сделать отдельным небольшим корнем, связанным с состоянием приложения. Так сохраняется исходный HTML статьи, метаданных и ссылок для поисковых систем, а Preact владеет только своей разметкой.
2. Перенести всю страницу в Preact. Дерево проще, но видимый сейчас в исходнике статьи текст исчезнет из первоначального HTML без отдельного предварительного рендеринга.
3. Оставить большую часть разметки под прямым управлением DOM и внедрить несколько компонентов Preact. Меньше первый шаг, но две модели управления одной формой усложнят состояние и дальнейшие изменения.

**Граница работ:** сохранить Rollup, `tools/index.mjs`, глобальный браузерный Typograf, CSS-классы и статическую публикацию. Новую маршрутизацию, смену сборщика и переделку визуального дизайна не включать. В `src/html/index.html` сейчас всегда стоит `page_desktop`; ветка `page_mobile` в коде и стилях фактически не активируется. Миграция сохраняет это поведение; включение мобильного режима требует отдельного решения.

## Этапы

### 1. Зафиксировать поведение до миграции

- [ ] В окружении с Node/npm выполнить `npm test` и `npm run build`; сохранить результаты, размеры `dist/index.js` и итогового `index.html`.
- [ ] Зафиксировать сценарии в браузере: ввод и очистка текста; восстановление из localStorage и `#!text=...`; обычный текст, HTML и JSON; длинный текст (> 10 000 символов); виды результата «Текст», «HTML», «Изменения»; копирование и сохранение; настройки правил, локали, HTML-сущностей и сброс; русский/английский интерфейс; открытие `#!prefs`.
- [ ] Отдельно проверить узкий экран: исходный сайт остаётся в `page_desktop`, а не переключается в `page_mobile`.

**Готово, когда:** есть исходная контрольная матрица и понятны уже существующие ошибки, которые не следует ошибочно приписывать миграции.

### 2. Подключить Preact и выделить корни

**Файлы:** `package.json`, `package-lock.json`, `tsconfig.json`, `rollup.config.mjs`, `src/index.ts`, `src/html/index.html`.

- [ ] Добавить `preact`; настроить TSX через `jsx: react-jsx` и `jsxImportSource: preact`, убедиться, что Rollup обрабатывает `.tsx`. `preact/compat` не нужен: зависимостей от React здесь нет.
- [ ] Выделить контейнер для шапки, редактора и настроек и отдельный контейнер для переключателя языка в подвале. Оставить статью, SEO-метаданные, футерные ссылки и текущий порядок подключения Typograf/JS в HTML.
- [ ] Определить явный мост между двумя корнями для смены языка; Preact не должен управлять узлами вне своих контейнеров.
- [ ] Сохранить имена CSS-классов на первом проходе, чтобы миграцию логики можно было проверить без переписывания стилей.

**Готово, когда:** минимальное Preact-приложение собирается прежней командой и итоговая страница по-прежнему открывается как статический `index.html`.

### 3. Перенести состояние и редактор

**Файлы:** `src/components/app/app.ts` → `.tsx`, `src/components/input/input.ts` → `.tsx`, `src/components/result/result.ts` → `.tsx`, `src/components/header/header.ts` → `.tsx`, `src/components/languageSelector/languageSelector.ts` → `.tsx`; сохранить при необходимости чистые функции в `src/helpers/`.

- [ ] В `App` хранить исходный текст, обработанный результат, выбранный вид результата, активную вкладку и язык. Экземпляр Typograf и сохранение настроек через `config.ts` оставить за границей представления.
- [ ] Сделать поле ввода управляемым Preact; обработку текста вызывать по тем же событиям, что сейчас. Сохранить восстановление текста и параметров адреса.
- [ ] Перенести переключение вкладок и `#!prefs` в состояние приложения, с синхронизацией hash и прокрутки страницы; проверить прямой вход по ссылке и возврат в редактор.
- [ ] Перенести три вида результата. Сохранить отложенное построение результата для ввода длиннее 10 000 символов и отменять устаревшие отложенные обновления, чтобы старый результат не перезаписывал новый.
- [ ] Проверить HTML-предпросмотр и diff: пользовательский текст и значения локализации не должны попадать в HTML без осознанного экранирования. Зафиксировать текущие правила показа HTML и отдельно согласовать любое изменение этих правил.

**Готово, когда:** ввод, обработка, переключение вида, вкладки и восстановление после перезагрузки работают без прямых изменений DOM в компонентах редактора.

### 4. Перенести настройки и действия

**Файлы:** `src/components/prefs/prefs.ts` → `.tsx`, `src/components/copyIcon/copyIcon.ts`, `src/components/saveFileIcon/saveFileIcon.ts`, `src/components/shareIcon/shareIcon.ts`, `src/components/tooltip/tooltip.ts`; при необходимости выделить подкомпоненты групп правил рядом с `prefs`.

- [ ] Представить локаль, режим сущностей, признак невидимых символов и включённые правила как состояние; список и группы правил получать из Typograf, сохраняя сортировку и исключение `live`-правил.
- [ ] Перенести «выбрать все», частичное состояние общего флажка, раскрытие групп и «по умолчанию». После любого изменения обновлять тот же экземпляр Typograf и сохранять текущие ключи localStorage.
- [ ] Перенести копирование, сохранение, системный share и уведомления, сохранив имена целей метрики и различие в доступности `navigator.share`.
- [ ] Исключить создание повторных обработчиков и таймеров при повторном рендере; для внешних событий предусмотреть очистку при размонтировании.

**Готово, когда:** каждый пункт настроек влияет на результат и переживает перезагрузку, а действия и метрика вызываются по одному разу.

### 5. Перевести локализацию и удалить старое управление DOM

**Файлы:** `src/i18n/i18n.ts`, `src/i18n/init.ts`, `src/components/extension/extension.ts`, затронутые компоненты и `src/html/index.html`.

- [ ] Внутри Preact выводить переводы из состояния языка. Сканирование `data-text-id` и запись `innerHTML` ограничить статическими узлами вне корней Preact либо заменить для них явным обновлением.
- [ ] При смене языка обновлять подписи, заголовки правил, список локалей, placeholder/title и текст уведомлений; сохранить перевод статических элементов страницы и заголовка документа.
- [ ] Перенести браузерную ссылку на расширение из побочного эффекта `extension.ts` в управляемый подвал или оставить её строго за пределами корня Preact.
- [ ] Удалить более не используемые классы прямого управления DOM и их импорты; оставить только действительно нужные браузерные интеграции.

**Готово, когда:** язык меняется без потери введённого текста и состояния настроек, и один и тот же DOM-узел не редактируют одновременно Preact и старый код.

### 6. Проверить результат и подготовить выпуск

- [ ] Добавить проверки для чистой функции обработки текста и настройки правил, а также браузерные сценарии для ввода, видов результата, настроек, локализации, hash, localStorage и действий. Автотесты здесь оправданы: меняется способ управления всей формой, тогда как нынешний `npm test` не проверяет поведение в браузере.
- [ ] Выполнить `npm test` и `npm run build`; открыть собранный `index.html` через локальный HTTP-сервер. Сравнить исходный HTML статьи и метаданных, поведение на широком и узком экранах и размер итоговой загрузки с исходной контрольной точкой.
- [ ] Обновить `README.md` с командами разработки и описанием Preact-корней. Выпускать только после прохождения контрольной матрицы из этапа 1.

**Основной риск:** `prefs.ts` (~500 строк) совмещает генерацию разметки, состояние правил и сохранение; его лучше переносить как отдельный этап после рабочего редактора. Второй риск — локализация через глобальный `innerHTML`, которая может конфликтовать с рендерингом Preact. Оба риска проверяются до удаления старой реализации.

## Дополнение: HTML до загрузки JavaScript

По уточнению требований интерактивный интерфейс также должен присутствовать в исходном HTML. Для статического хостинга это выполняется при сборке: `tools/build-ssr.mjs` создаёт серверный модуль, а `tools/index.mjs` вставляет результат `preact-render-to-string` в `#app` и `#language-selector`. Браузер использует `hydrate()` для состояния по умолчанию; при отличающихся данных в localStorage или hash он отрисовывает персонализированное состояние. Статья и SEO-метаданные по-прежнему остаются в исходном HTML. Сервер на каждый запрос не требуется.
