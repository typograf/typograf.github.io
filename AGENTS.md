# Инструкции для работы с проектом

## Проект и команды

- Это статический сайт Typograf с интерфейсом на Preact и TypeScript 6. Используйте Node.js 24.22.1 или новее (версия для nvm — в `.nvmrc`) и npm с `package-lock.json`.
- Установка зависимостей: `npm ci`. Проверки: `npm test` (ESLint, TypeScript, сборка и Vitest). Отдельная сборка: `npm run build`.
- После изменений интерфейса или сборки проверяйте `npm test`: команда включает сборку. Для ручной проверки откройте собранный сайт через локальный HTTP-сервер, например `python3 -m http.server 8000`.

## Структура и сборка

- `src/components/` содержит компоненты Preact; `Button`, `Tooltip` и `Textarea` размещайте в `src/components/ui/`. Папка компонента называется в PascalCase, основной файл — `index.ts` или `index.tsx`, стили — `index.css`. SVG-иконки храните в папке `assets` соответствующего компонента, хуки — в его папке `hooks/`, тесты — рядом с ним. Общие функции размещайте в `src/helpers/`, переводы — в `src/i18n/`.
- Для BEM-классов используйте `block` из `src/helpers/bem.ts`.
- Внутренние утилиты компонента храните в файле `utils.ts` рядом с ним.
- Типы компонента храните в файле `types.ts` рядом с ним.
- Общая конфигурация хранится в `src/lib/Config.ts`.
- Для объединения CSS-классов используйте пакет `classnames`.
- `src/index.ts` подключает клиентские корни Preact к готовой разметке. `src/ssr.tsx` создаёт разметку при сборке. Сохраняйте совместимость первоначального HTML и гидратации, включая настройки из localStorage и параметры URL.
- `src/html/index.html` — исходный шаблон страницы. `tools/build-ssr.mjs` и `tools/index.mjs` создают корневой `index.html`, встраивая HTML, CSS и JavaScript. Сборка клиентского кода настроена в `rollup.config.mjs`; не добавляйте второй сборщик для этой задачи без необходимости.
- Корневой `index.html` генерируется командой сборки и игнорируется Git. Правьте шаблон и исходники, затем запускайте `npm test` или `npm run build`.
- `.github/workflows/tests.yml` запускает `npm test` и упаковывает файлы в `build/pages` по запросу workflow `.github/workflows/pages.yml`. Публикация выполняется только из `master` после успешных проверок. При изменении локальных ресурсов обновляйте список упаковываемых файлов.
- Исходники статьи — `src/components/AboutArticle/`, русских метаданных — `src/components/SeoHead/`; сборка вставляет их в `src/html/index.html`. Статья, заголовок, метаданные, canonical и ссылки в собранном `index.html` должны оставаться доступными без выполнения JavaScript: сайт публикуется без отдельного SSR-сервера. При изменении SSR проверяйте `tools/ssr.test.mjs`.

## Поведение и безопасность

- Сохраняйте существующие ключи localStorage, формат hash-ссылок, работу настроек, локализации, трёх видов результата и действий редактора, если задача прямо не требует их изменения.
- Пользовательский HTML в предпросмотре проходит через DOMPurify перед `dangerouslySetInnerHTML`; diff экранирует текст. Не вставляйте пользовательские строки в HTML без безопасной обработки. При изменении этого пути обновляйте соответствующие тесты.
- Для новых обработчиков и эффектов Preact соблюдайте зависимости хуков и очищайте таймеры и подписки. Применяйте `useCallback` там, где нужна стабильная ссылка на функцию, а не механически для каждого обработчика.
